# 桌面应用帮助手册更新

## 适用场景

当任务满足以下条件时，使用这个 skill：

1. 可以实际打开并操作目标桌面应用
2. 需要编写、更新、校准或重写该应用的帮助手册
3. 最好已有项目级手册规范、历史手册、发行说明或其它现有资料；如果没有，也可以从零编写

这类工作流通常依赖高级多模态模型来同时处理：

1. 界面观察与状态辨识
2. 截图质量判断
3. 文档结构对齐
4. 现有资料与真实界面差异归纳

因此，默认应使用当前可用的高级多模态模型，并开启高推理强度。不要用仅擅长纯文本生成的轻量模型承担整条流程。

截图与桌面操作相关说明：

- 当前这套本机截图能力说明基于 Deepin V25 环境验证
- 其它桌面环境、发行版、会话类型或设备暂未做适配与测试
- 涉及真实截图时，应优先参考 `references/local-screenshot-playbook.md`，不要默认假设其它环境具备同样能力

## 默认立场

先由 agent 判断当前任务更适合：

- 在现有手册基础上做增量更新
- 以现有资料为参考进行大幅重写
- 基于真实产品行为从零编写新手册

如果 agent 无法可靠判断，就向人类确认，而不是武断假设。

无论采用哪种写法，都遵循以下原则：

- 以真实运行中的应用为事实来源
- 优先复用可信、未过时的现有资料
- 不为了“保持原样”而保留错误内容
- 不为了“全部重写”而丢失已有的有效结构和术语

判断路线时，优先加载：

- `references/decision-guide.md`

如果判断为“从零编写”，且项目没有现成的手册规范或可复用结构，直接加载：

- `references/from-scratch-manual-spec.md`

如果任务需要真实截图，优先加载：

- `references/local-screenshot-playbook.md`

## 最小工作流

只在这里保留简版导航；详细执行步骤按需加载：

- 先收集可用输入：应用、现有资料、规范文件、发行说明
- 决定是增量更新、大幅重写还是从零编写
- 建立文档计划或从零编写大纲、功能核验矩阵和截图登记
- 串行探索真实应用，逐项核验关键流程和状态
- 生成或准备符合产品语境的演示数据
- 截图后立即复核，导出类功能必须验证文件落盘
- 按项目规范、从零编写规范或通用规范写手册并完成最终检查
- 将产物输出到对应系统非系统盘根目录的 `output` 文件夹，并在交付时给出最短可打开路径

需要详细步骤、风险和完成检查时，加载：

- `references/workflow.md`
