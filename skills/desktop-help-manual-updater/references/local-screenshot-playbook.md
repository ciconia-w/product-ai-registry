# 本机截图说明（已验证）

这份说明只描述**当前这台本地设备**上已经实际验证过的截图能力，不对其它 agent、其它桌面环境或其它操作系统做泛化承诺。

## 适配与测试范围说明

当前说明基于：

- Deepin V25
- X11 会话
- 当前本机已安装工具与默认桌面组件

请直接告知使用者：

- 这份截图说明目前只针对 Deepin V25 环境做过验证
- 其它设备、其它发行版、其它桌面环境、Wayland 会话或远程桌面场景暂未做适配与测试
- 如果不在上述环境内，不应直接照搬此说明，应先重新验证截图链路

## 已验证环境

本机当前环境：

- 操作系统桌面：Deepin
- 会话类型：X11
- `DISPLAY=:0`
- 已验证截图工具：`/usr/bin/deepin-screen-recorder`
- 已验证图片打开方式：`gio open`、`xdg-open`

已实际验证的最小闭环：

1. 命令行调用 `deepin-screen-recorder`
2. 成功生成 PNG 文件
3. 文件可落盘
4. 本机默认图片查看器可打开 PNG

## 首选截图能力

在这台设备上，首选使用：

```bash
deepin-screen-recorder
```

原因：

1. 已在本机真实执行成功
2. 直接支持命令行全屏截图
3. 可直接指定保存路径
4. 与当前 Deepin 桌面环境匹配

## 已验证命令

### 1. 全屏截图并直接保存

```bash
deepin-screen-recorder -f -s "/目标路径/full.png" -n
```

说明：

- `-f`：全屏截图
- `-s`：指定保存路径
- `-n`：不发送通知，减少干扰

在本机已验证此命令可成功生成 PNG 文件。

### 2. 延迟后全屏截图

```bash
deepin-screen-recorder -d 3 -f -s "/目标路径/full.png" -n
```

适用场景：

- 需要先展开菜单、打开弹窗、切到目标窗口，再截图

### 3. 截图最上层窗口

```bash
deepin-screen-recorder -w -s "/目标路径/top-window.png" -n
```

说明：

- `-w` 用于抓取最上层窗口
- 这条命令可作为候选能力，但在当前会话里我没有像全屏截图那样做完整落盘验证
- 真正依赖它交付前，应先做一次小规模验证

## 打开并复核截图

在这台设备上，可优先使用以下方式打开截图文件：

```bash
gio open "/目标路径/full.png"
```

或：

```bash
xdg-open "/目标路径/full.png"
```

本机 `image/png` 当前默认关联到了 Deepin 的图片查看器，可用于人工复核截图。

## 建议的落盘与命名方式

手册类任务建议把截图放到手册输出目录内的 `fig/` 子目录，例如：

```text
<output>/<产品名>/fig/p01-home.png
<output>/<产品名>/fig/p02-settings.png
```

命名规则建议：

1. 使用稳定前缀，例如 `p01`、`p02`
2. 名称里包含场景关键词，例如 `home`、`settings`、`export-dialog`
3. 不要使用 `截图1.png`、`新建位图.png` 这类不可回溯名称

## 本机推荐执行顺序

在当前设备上做截图，推荐按以下顺序执行：

1. 先确定最终保存目录
2. 如果需要，先用 `-d` 预留准备时间
3. 执行 `deepin-screen-recorder` 截图并落盘
4. 用 `file` 或 `stat` 确认文件已生成
5. 用 `gio open` 或 `xdg-open` 打开截图复核
6. 通过后再在手册中引用该图片

## 最小验证方式

如果 agent 不确定截图链路是否仍然可用，先做一个最小验证：

```bash
tmpdir=$(mktemp -d)
deepin-screen-recorder -f -s "$tmpdir/test.png" -n
file "$tmpdir/test.png"
```

只有在确认截图真实落盘后，才进入正式批量截图阶段。

## 什么时候不要硬做截图

出现以下情况时，不要假设截图一定能成功：

1. 会话类型不再是 X11
2. `deepin-screen-recorder` 不存在
3. 当前窗口受权限、沙箱或安全策略限制无法捕获
4. 无法确认保存路径是否可写

这些情况下，应先重新做最小验证；如果仍不可靠，再改为人工截图或向人类确认。

## 这份说明的边界

这份文档只承诺以下能力已经在本机验证过：

1. `deepin-screen-recorder` 的全屏截图落盘
2. `gio open` / `xdg-open` 打开 PNG

它**不承诺**以下能力一定可用：

1. 其它截图软件
2. Wayland 下的同样行为
3. 区域截图、滚动截图、OCR 截图一定稳定
4. 其它 agent 运行环境具备同样能力
