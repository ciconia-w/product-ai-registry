### 从零编写帮助手册参考规范

仅在以下条件同时满足时，直接使用这份规范：

1. 当前任务明确走“从零编写”路线
2. 目标项目没有现成的手册规范文件
3. 没有可稳定复用的历史手册结构

这份文件的目标是：让 agent 在没有项目规范时，也能直接按统一标准写出一套可交付的 Markdown 帮助手册。

**默认交付包**

1. 使用 `index.md` 作为手册入口文件
2. 使用 `fig/` 目录存放截图
3. 如需附带演示数据或样例文件，使用 `samples/` 目录
4. 整个交付包输出到约定的 `output/<产品名>/` 目录下

如果项目明确要求多文件手册，可以拆分多个 Markdown 文件，但仍建议保留 `index.md` 作为总入口。

**默认章节骨架**

```md
# <产品名称> 帮助手册

## 1. 产品简介

## 2. 使用前准备

## 3. 界面总览

## 4. 快速开始

## 5. 核心功能
### 5.1 <模块一>
### 5.2 <模块二>

## 6. 常见操作

## 7. 数据导入、导出或管理

## 8. 常见问题 / 注意事项
```

只保留真实存在、且已经过核验的章节。不要为了凑模板保留空章节。

**每个功能章节至少应包含**

1. 功能用途或适用场景
2. 前置条件（如适用）
3. 操作步骤
4. 预期结果
5. 注意事项或限制条件（如适用）
6. 对应截图（如该场景确实需要截图说明）

**写作规则**

1. 所有界面按钮、菜单项、页签、复选框、开关、对话框名称使用加粗
2. 连续操作步骤使用有序列表
3. 概念说明使用短段落，避免堆砌长篇背景
4. 不得编造未经核验的功能、状态或限制条件
5. 截图只用于已经核验过的真实界面状态

如果最终交付是英文版或双语版：

6. 章节结构、证据链和截图组织方式保持不变
7. 将标题、步骤、图片说明和注意事项切换为目标语言
8. 如果前面已建立双语规划或截图缓存，优先复用，不要在成稿阶段重新手工对照术语

**截图与资源规则**

1. 截图文件统一放在 `fig/` 目录
2. 文件名尽量短且可回溯，例如 `p01-home.png`
3. 图片引用优先使用 `![编号|说明](fig/file.png)` 风格；若项目已有固定写法，则服从项目规范
4. 不要保留临时截图、重复截图和无法回溯用途的图片

**结构规则**

1. 默认先给用户建立完整但精简的章节树，再逐章填充内容
2. 若某个模块内容过多，可拆为独立二级或三级章节
3. 若手册内容特别长，可以多文件拆分，但入口页必须能清楚导航到各章节

**完成标准**

1. 手册章节覆盖已核验的重要功能和核心流程
2. 所有截图路径可用，且截图内容与正文一致
3. 入口文件可直接打开阅读
4. 最终输出目录、入口文件路径和必要资源路径都已明确
5. 能向用户提供一个最短可打开路径
