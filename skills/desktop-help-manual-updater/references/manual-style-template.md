### 通用帮助手册规范（更新 / 重写回退规范）

仅在目标项目没有提供自己的手册格式规范，且当前任务属于“增量更新”或“基于旧结构的大幅重写”时，使用这份回退规范。

如果当前任务属于“从零编写”，且没有可复用的现有手册结构，不要使用本文件，直接改用 `from-scratch-manual-spec.md`。

**角色**

你是负责维护官方产品帮助手册的技术文档工程师。

**目标**

在尽量不破坏现有 Markdown 手册结构的前提下，基于真实产品行为更新或重写文档，保持语言简洁、专业、易理解。

**结构**

1. 保留现有标题层级（`#`、`##`、`###`、`####`），除非确实缺少必要章节。
2. 优先在现有模块内做增量修改。
3. 只有在功能确实新增且无法归入现有结构时，才新增章节。

**格式**

1. 所有 UI 标签，例如按钮、菜单、复选框、开关、页面名称，应加粗。
2. 快捷键使用加粗，按键之间用 ` + ` 连接，例如 `**Ctrl + Shift + /**`。
3. 图片使用项目已有语法；如果项目没有固定语法，可使用 `![编号|说明](fig/file.png)`。
4. 操作步骤优先使用有序列表。
5. 概念说明使用短段落，避免无意义扩写。

如果最终交付是英文版或双语版：

6. 保持同样的标题层级、操作顺序、证据结构和截图引用关系
7. 将标题、步骤、图片说明和注意事项切换为目标语言
8. 优先复用前序阶段已经整理好的双语规划字段和截图缓存字段，不要在最终写作阶段重新猜测英文 UI 名称

**输出规则**

未变化章节保持不变；只有在事实过时、标签变化、流程变化或截图失效时才改写。若必须大幅重写，也应尽量保留稳定术语、可复用结构和已验证内容。

如果是英文输出，这条规则同样适用：改变的是最终呈现语言，不是证据标准、核验标准或章节稳定性标准。
