# 路线判断指南

## 目标

在正式写手册前，先判断当前任务更适合：

1. 增量更新
2. 大幅重写
3. 从零编写

不要一上来就默认走某一条路线。

## 判断顺序

先看以下四类信号：

1. 现有手册是否存在
2. 现有手册结构是否可复用
3. 现有术语和模块划分是否仍然可信
4. 可用资料是否足以支撑从零编写

## 选择“增量更新”的信号

通常满足以下大部分条件时，优先增量更新：

- 已有手册覆盖了大多数核心模块
- 现有目录结构基本合理
- 现有术语与界面标签大体一致
- 变化主要集中在少数模块、少数流程或局部截图

经验上，如果现有手册的结构和内容有 70% 以上仍可复用，可优先考虑增量更新。

## 选择“大幅重写”的信号

通常满足以下大部分条件时，优先大幅重写：

- 已有手册存在，但大量步骤、截图或结构已经过时
- 目录结构还能部分复用，但章节内内容需要重写
- 术语有一定参考价值，但不能直接沿用全文
- 产品经历了多模块改版，继续修补旧文档成本过高

经验上，如果只有 30% 到 70% 的结构仍有价值，可优先考虑大幅重写。

## 选择“从零编写”的信号

通常满足以下任一强信号时，优先从零编写：

- 没有现成手册
- 现成手册与当前产品严重失配，继续修补没有意义
- 只有发行说明、零散资料或口头说明，没有成体系文档
- 用户明确要求新写一套手册

经验上，如果现有手册几乎不可复用，或者可复用结构低于 30%，应优先考虑从零编写。

## 必须询问人类的情况

出现以下情况时，不要自行拍板，先问人类：

- 输出语言不明确
- 交付格式不明确，例如单文件还是多文件都合理
- 应用无法正常打开或关键功能无法访问
- 多份现有资料彼此冲突，且无法自行判定以谁为准
- 无法可靠识别非系统盘输出路径

## 记录要求

完成路线判断后，使用：

- `references/templates.md` 中的“路线判断记录”

把结论记录下来，再进入后续执行。
